# v0.3.0 Skill Rename Migration

v0.3.0 keeps the Skill Suite at exactly 11 top-level Skills while making the two front-half workflow names describe their actual responsibility:

| Previous name | New name | Meaning |
| --- | --- | --- |
| `spec-driven-development` | `requirement-engineering` | Requirement Contract, reconciliation, conflict classification, and user decision gates |
| `planning-and-task-breakdown` | `change-planning` | Repository impact analysis, dependencies, risks, slices, and completion conditions |

The source repository target is also moving from `hugo2lee/agent-skills` to `hugo2lee/engineering-philosophy`. The GitHub repository rename is a maintainer action; until it is completed, the old URL may remain the active remote or redirect to the new URL.

## Migration order

Remove the old installed directories before installing the new names. This avoids leaving both names discoverable and prevents an Agent from selecting stale instructions:

```sh
npx skills@latest remove spec-driven-development planning-and-task-breakdown \
  --global \
  --yes

npx skills@latest add hugo2lee/engineering-philosophy \
  --skill '*' \
  --global \
  --agent codex \
  --agent cline \
  --yes
```

Confirm the result with:

```sh
npx skills@latest ls -g
```

The installed set should contain `requirement-engineering` and `change-planning`, and should not contain the two previous names. A user who has installed the suite into an explicit custom root should remove the corresponding old directories there instead of deleting unrelated Skills.

## Local remote after the GitHub rename

After a maintainer changes the repository name in GitHub Settings → General → Repository name, update existing clones:

```sh
git remote set-url origin git@github.com:hugo2lee/engineering-philosophy.git
git remote -v
```

Do not rewrite release tags while changing the repository identity. `v0.1.0`, `v0.2.0`, and `v0.2.1` remain immutable.
