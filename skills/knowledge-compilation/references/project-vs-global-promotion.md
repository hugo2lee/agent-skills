# Project and Global Promotion

Automatic knowledge generation defaults to project scope.

## Promotion path

```text
Project Observation
        ↓
Repeated Project Pattern
        ↓
Project Rule or Skill
        ↓
Independent evidence in another project
        ↓
Cross-project Candidate
        ↓
Eval and review
        ↓
engineering-philosophy promotion
```

The project may automatically register and validate its own knowledge. It may
not automatically edit the global engineering-philosophy repository or create
a global `MUST` rule from one project's evidence.

## Promotion evidence

Promotion is justified by repeated independent projects, a high-cost incident
that yields a clearly general safeguard, or repeated review findings of the
same failure mode. The candidate must remove project paths, product facts,
provider choices, and company constraints before entering the global Skill.

## Scope fields

Use explicit ownership scope:

```yaml
scope: project
```

`organization` and `global` are review outcomes, not automatic generation
defaults. A global Skill should describe reusable decisions and exclusions,
not the first project's folder names.
